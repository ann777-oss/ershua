# 二刷 · Ershua

> LLM 驱动的盐言故事**读后重审**游戏 —— 读完一个故事，再以侦探身份重返案内。

知乎黑客松作品。玩家不再是读者，而是接手旧案的侦探：**自由盘问**故事里的角色、**划选原文**注册证据、在证据板上拼出暗线，最后带上证据走进审讯室**对峙破谎**。

## 玩法循环

```
案卷速读 → 审讯室自由盘问 → 划原文注册证据 → 证据板关联拼暗线 → 对峙(证据戳破谎言) → 结案结算
```

- **自由盘问**：想问什么问什么，LLM 扮演角色在「知识边界」内作答——没读过原文的角色不会知道真相，撒谎的角色会守住谎。诈问、迂回、施压三种策略都有真实效果。
- **证据系统**：证据不是点按钮领取，而是从故事**原文里划选**出来注册的，注册时要答对「这段话为什么是证据」。
- **对峙**：在审讯中亮出正确证据，戳破角色证词里的矛盾，暗线推进直至结案。
- **叙事流水线**：新故事（知乎盐言故事内容 API）→ 暗线表草稿 → 角色卡草稿 → 校验落盘 → 可玩，半自动把任意盐言故事变成一桩可重审的案子。

## 快速开始

```bash
cd game
npm install

# 配置 LLM Key（不配也能玩，自动降级离线剧本模式，页面有角标提示）
cp .env.example .env   # Windows: copy .env.example .env
# 编辑 .env 填入 DEEPSEEK_API_KEY

npm run dev            # 前端 http://localhost:5173 + 后端 http://localhost:3001
```

生产模式（单端口 3001，静态页 + API）：

```bash
cd game
npm run build
npm start
```

环境要求：Node 20+。API Key 仅存于 `game/.env`（已 gitignore），LLM 不可用时自动降级为离线剧本模式，游戏全程可玩。

## 目录结构

```
game/
├── src/            # 前端：Vite + React 18 + Zustand（案卷/审讯/证据板/对峙/结案/分享/故事库）
├── server/         # 后端：Express + DeepSeek（openai SDK 兼容模式），无状态 LLM 编排 + SSE 流式
├── shared/         # 剧本数据：内置主线 + 流水线落盘的自定义故事（JSON，无数据库）
├── eval/           # 各阶段验收脚本与报告（P0-P4：盘问 30 问测试集 / 证据 / 对峙 / 流水线）
└── scripts/        # 数据迁移与流水线复现脚本
数据资产/            # 源数据：故事与伏笔表、证据注册表、角色卡（游戏骨架的确定性数据层）
design.md           # 视觉设计规范（案件卷宗 Paper Dossier 风格）
开发Spec.md         # 开发规格（架构、API 契约、阶段门）
```

## 架构

混合式：游戏骨架（暗线 / 证据解锁 / 状态机）用**确定性数据驱动**（`数据资产/` 与 `game/shared/` 下的 JSON），LLM 只负责它擅长的部分——审讯自由对话、回答判定、叙事流水线。客户端持有游戏状态，服务端无状态。

**技术栈**：Vite ｜ React 18（plain CSS + design tokens）｜ Zustand ｜ Node 20 + Express ｜ DeepSeek API
